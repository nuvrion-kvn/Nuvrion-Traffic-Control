**Nuvrion Traffic Control** управляет входящими соединениями Linux-сервера через собственную таблицу nftables. Загружает три списка IP/CIDR, проверяет их содержимое и объединяет с ручными блокировками. Исключения для администратора и панели имеют приоритет.

Поддерживает IPv4 и IPv6, восстановление правил после перезагрузки, обновления по таймеру, журнал и статистику срабатываний. Установка начинается после подтверждения; управление доступно через русское меню или команду `ntc`. Эффективность фильтрации зависит от содержимого внешних списков.

## Возможности

| Компонент | Назначение |
|---|---|
| Фильтрация | Собственная таблица `inet nuvrion_tc`, входящий IPv4 и IPv6 |
| Внешние списки | `antiscanner`, `government_networks`, `skipa` |
| Ручное управление | Блокировки IP/CIDR и исключения отдельных IP |
| Обновления | Загрузка всех источников, проверка и применение правил |
| Автозапуск | Восстановление локальных правил после перезагрузки |
| Статистика | Топ IP по журналу блокировок и организации через RDAP |
| Самодиагностика | Зависимости, конфигурация, права, правила, службы и таймеры |
| Интерфейс | Русское меню, отчёт о компонентах, адаптивная ширина и фирменная шапка |

## Быстрая установка

Рабочая короткая команда с автоматическим определением IP текущего SSH-подключения:

```bash
curl -fsSL https://github.com/nuvrion-kvn/Nuvrion-Traffic-Control/releases/latest/download/nuvrion-traffic-control.py -o ntc.py && sudo env SSH_CONNECTION="${SSH_CONNECTION:-}" python3 ntc.py install
```

Скрипт будет сохранён в текущем каталоге как `ntc.py`, после чего запустится интерактивная установка.
Для установки с обязательной проверкой контрольной суммы используйте полный вариант ниже.

## Установка с проверкой SHA-256

Нужны **root, Python 3.10+ и работающий systemd**. Поддерживаемые ОС — Ubuntu 22.04/24.04 и Debian 12.
Недостающие `nftables` и `ca-certificates` устанавливаются через apt после согласия на установку.
Python должен быть установлен заранее. Проверки проекта запускаются в GitHub Actions; полная матрица серверных ОС требует отдельной проверки.

Скачайте скрипт и контрольную сумму из последнего опубликованного выпуска:

```bash
curl -fsSLo nuvrion-traffic-control.py \
  https://github.com/nuvrion-kvn/Nuvrion-Traffic-Control/releases/latest/download/nuvrion-traffic-control.py &&
curl -fsSLo SHA256SUMS \
  https://github.com/nuvrion-kvn/Nuvrion-Traffic-Control/releases/latest/download/SHA256SUMS &&
sha256sum -c SHA256SUMS &&
sudo env SSH_CONNECTION="${SSH_CONNECTION:-}" python3 ./nuvrion-traffic-control.py install
```

Скрипт покажет аннотацию и обязательно запросит подтверждение установки. Параметр `--yes` считается
явным согласием, переданным пользователем в команде. IP администратора и порт SSH предлагаются
из текущего подключения: подтвердите их или введите свои. Для панели используются подходящие настройки
Vision Installer (`panel_ips` в `/opt/remnanode/settings.json`), иначе потребуется ручной ввод.
Нужен **исходящий IP панели**: адрес домена за CDN может отличаться от него.

После проверки и сохранения конфигурации фильтрация, восстановление после перезагрузки и ежедневное
обновление включаются автоматически. Затем появятся отчёт о компонентах и главное меню. Проверьте состояние:

```bash
sudo ntc s
```

Проверьте новое SSH-подключение и связь панели с нодой. До завершения проверки держите доступной
консоль провайдера.

Существующий TrafficGuard требуется сначала штатно удалить; автоматического переноса его настроек нет.
Если Traffic Control уже установлен, используйте **[инструкцию обновления](docs/UPDATE.md)**.

<details>
<summary>Установка с явно заданными параметрами</summary>

Замените адреса и порт примера своими значениями. `--yes` пропускает вопросы, `--allow` можно повторять.
Параметры из `SSH_CONNECTION` в этом режиме не добавляются.

```bash
sudo python3 ./nuvrion-traffic-control.py install \
  --yes --ssh-port 22 --allow 198.51.100.10 --allow 198.51.100.20
```

## Команды

Главное меню: **`sudo ntc`**. Для root префикс `sudo` не нужен.

| Команда | Назначение |
|---|---|
| `ntc s` | Состояние, дата обновления, количество записей и исключения |
| `ntc t` | Топ-10 IP и организаций за 24 часа |
| `ntc t --no-resolve` | Топ без обращений к RDAP |
| `ntc l` | Последние блокировки и журнал обновлений |
| `ntc c` | Самодиагностика |
| `ntc fix` | Исправление обнаруженных проблем с подтверждением |
| `ntc r` | Полные правила nftables |
| `ntc u` | Обновить три списка и применить их, если фильтрация включена |
| `ntc on` | Включить фильтрацию, восстановление и автообновление |
| `ntc off` | Выключить фильтрацию и автообновление |
| `ntc --help` | Справка по полным командам |
| `ntc --version` | Версия установленного файла |

Команды для списков (вместо примеров укажите нужные IP):

```bash
sudo ntc ban 203.0.113.0/24
sudo ntc unban 203.0.113.0/24
sudo ntc allow 203.0.113.7
sudo ntc disallow 203.0.113.7
```

`unban` удаляет точную ручную запись. Адрес может остаться в другом диапазоне или внешнем списке.
`allow` добавляет отдельный IP в исключения, которые имеют приоритет над блокировками.
Последнее исключение удалить нельзя. Машинный статус: `ntc status --json`.

## Как применяются правила

1. Loopback и установленные/связанные соединения пропускаются этой таблицей.
2. Настроенные TCP-порты SSH пропускаются этой таблицей.
3. IP администратора, панели и другие исключения пропускаются этой таблицей.
4. Новые обращения от IP из объединённых внешних и ручных списков блокируются.

**Настроенные SSH-порты исключены из блокировок Traffic Control — в том числе для адресов из списков.**
Попытки входа могут оставаться в журнале sshd. Их ограничивают настройки SSH, Fail2ban и другие правила
firewall. `return` в таблице Nuvrion не отменяет ограничения UFW или других таблиц.

Охватывается **INPUT**: сам сервер и контейнеры с `network_mode: host`. Docker bridge, транзитный
и исходящий трафик не фильтруются. Это фильтр по спискам адресов; обнаружение любых сканов по поведению
и защита пропускной способности канала в него не входят. Внешние списки могут давать ложные блокировки.

## Автоматическое обновление

После включения работает `nuvrion-traffic-control-update.timer`: первый запуск запланирован
через 15 минут после загрузки, следующие — примерно раз в сутки, с задержкой до 30 минут.
Ошибка любого источника останавливает обновление: прежние списки сохраняются.
При выключенной фильтрации ручная `ntc u` обновляет локальные данные без включения правил.

```bash
systemctl list-timers nuvrion-traffic-control-update.timer --all --no-pager --full
systemctl show nuvrion-traffic-control-update.service -p Result -p ExecMainStatus
```

Таймер обновляет **списки и правила**. Новый программный релиз устанавливается отдельно
по [инструкции обновления](docs/UPDATE.md).

## Диагностика и журналы

```bash
sudo ntc c
sudo ntc s
sudo ntc t
```

`sudo ntc fix` предлагает восстановление файлов, служб и правил, сохраняя выбор включённой/выключенной
фильтрации. После сторонней очистки firewall эта команда может восстановить таблицу.

Пустой топ означает отсутствие подходящих записей журнала, а не доказательство неисправности.
Топ считает до 10 000 записей за 24 часа. Логирование ограничено по частоте; колонка «Пакетов»
в топе отражает журнал. Полные счётчики совпадений смотрите в правилах:

```bash
sudo nft list chain inet nuvrion_tc ingress
```

Ненулевой `counter packets` перед `drop` показывает блокировки с момента создания текущей таблицы.
Счётчики сбрасываются при её пересоздании или перезагрузке. Добавленная блокировка не разрывает
установленное соединение — проверять нужно новое подключение.

RDAP передаёт IP из топа внешнему сервису и реестрам, кэширует результат на семь дней и показывает
владельца сети, который не обязательно является отправителем обращения. Без внешних запросов:
`ntc t --no-resolve`. При пустом топе выводится одна строка. В низком терминале меню показывает до пяти
записей, отдельная команда `ntc t` — до десяти. Цвета отключаются при `NO_COLOR` и перенаправлении вывода;
псевдографика требует терминал UTF-8.

Логирование включено по умолчанию; `--no-logging` при установке отключает его и сбор топа.
Срок хранения записей задаётся системным journald.

## Удаление

```bash
sudo ntc off
sudo ntc uninstall --yes
```

Удаляются собственная таблица, программа, короткая команда и службы. Конфигурация остаётся
в `/var/lib/nuvrion-traffic-control/`. Повторная установка проверяет и восстанавливает сохранённую
конфигурацию, после чего включает фильтрацию.
